# Функциональные требования: GeoChange Monitor

## 1. Акторы

| Актор             | Роль                                                              |
|-------------------|-------------------------------------------------------------------|
| Оператор          | Основной пользователь: загружает снимки, просматривает результаты |
| ML-движок         | Программный агент: выполняет инференс, формирует маску изменений  |
| Postprocessor     | Программный агент: очищает маску, удаляет шум                     |
| Web Layer         | Программный агент: визуализация, карта, отчёт                     |

---

## 2. Функциональные требования

### FR-01 — Загрузка пары снимков

**Актор:** Оператор → Web Layer  
**Описание:** Оператор через веб-интерфейс загружает два снимка одной территории за разные даты. Система проверяет совместимость.

**Основной сценарий:**
1. Оператор открывает веб-интерфейс и загружает два файла (до/после)
2. Система проверяет размер, разрешение, CRS
3. При несовместимости — выводит ошибку с указанием причины
4. При успехе — сохраняет пару и присваивает `pair_id`

**Критерий приёмки:** Загрузка и валидация пары не более 10 секунд. Поддержка GeoTIFF, PNG, JPEG.

---

### FR-02 — Обнаружение изменений

**Актор:** ML-движок  
**Описание:** Система формирует маску изменений по паре снимков с помощью нейросетевой модели битемпоральной сегментации.

**Основной сценарий:**
1. Inference Engine загружает пару снимков
2. Выполняет forward pass модели
3. Возвращает маску изменений в виде вероятностей и бинарной маски
4. Сохраняет результат в `metadata.db` с `model_version`

**Критерий приёмки:** IoU ≥ 0,75 на тестовой выборке LEVIR-CD.

---

### FR-03 — Постобработка маски

**Актор:** Postprocessor  
**Описание:** Система применяет морфологические операции и фильтрацию по площади для удаления шумовых срабатываний.

**Основной сценарий:**
1. Postprocessor получает сырую маску от модели
2. Применяет открытие/закрытие (kernel 3×3)
3. Удаляет объекты площадью менее порога (по умолчанию 20 пикселей)
4. Сглаживает границы

**Критерий приёмки:** Прирост Precision ≥ 5% без снижения Recall более чем на 2%.

---

### FR-04 — Векторизация результатов

**Актор:** Postprocessor → Vectorizer  
**Описание:** Система преобразует бинарную маску в векторные объекты с координатами и площадями.

**Основной сценарий:**
1. Vectorizer получает очищенную маску
2. Выполняет контурирование (OpenCV findContours)
3. Преобразует контуры в полигоны GeoPandas
4. Рассчитывает площадь и центроид каждого объекта
5. Экспортирует в GeoJSON

**Критерий приёмки:** Корректный GeoJSON, открывающийся в QGIS без ошибок.

---

### FR-05 — Визуализация на карте

**Актор:** Web Layer  
**Описание:** Система отображает маску изменений на карте с наложением на спутниковую подложку.

**Основной сценарий:**
1. Web Layer получает GeoJSON с объектами изменений
2. Отображает их на карте Leaflet с полупрозрачной заливкой
3. При клике на объект — показывает площадь, координаты, уверенность

**Критерий приёмки:** Отображение не более 5 секунд после инференса.

---

### FR-06 — Формирование отчёта

**Актор:** Web Layer → Report Generator  
**Описание:** Система формирует отчёт с таблицей изменений.

**Основной сценарий:**
1. Report Generator получает список объектов изменений
2. Формирует таблицу: `object_id, type, area_m2, lat, lon, confidence`
3. Экспортирует в CSV и PDF

**Критерий приёмки:** Экспорт в CSV и PDF, корректное отображение кириллицы.

---

### FR-07 — Cold-start

**Актор:** ML-движок  
**Описание:** При отсутствии обученной модели система переключается на baseline-методы.

**Основной сценарий:**
1. Inference Engine проверяет наличие `model.pt`
2. Если файл не найден — загружает `baseline.py`
3. Baseline применяет разность каналов, NDVI-разность, SSIM
4. Предикты логируются с флагом `model_version = "baseline"`

**Критерий приёмки:** Система функционирует с первого запуска без ML-модели.

---

### FR-08 — Сравнение моделей

**Актор:** Оператор  
**Описание:** Система позволяет запустить несколько моделей на одной паре и сравнить результаты.

**Основной сценарий:**
1. Оператор выбирает 2+ модели в веб-интерфейсе
2. Система выполняет инференс каждой
3. Выводит таблицу метрик (IoU, F1, Precision, Recall) и визуальное сравнение масок

**Критерий приёмки:** Вывод метрик и визуальное сравнение не более 30 секунд.

## 3. Нефункциональные требования

| ID     | Требование               | Значение                                          |
|--------|--------------------------|---------------------------------------------------|
| NFR-01 | Латентность инференса    | < 5 с на пару 512×512 (CPU)                       |
| NFR-02 | Потребление памяти       | < 500 МБ (Python runtime + модель)                |
| NFR-03 | Платформа                | Linux / Windows (CPU-only)                        |
| NFR-04 | Размер модели (диск)     | < 200 МБ                                          |
| NFR-05 | Минимальный датасет      | ≥ 500 пар снимков для обучения                    |
| NFR-06 | Доступность системы      | Работа без облачных сервисов                      |
| NFR-07 | Воспроизводимость        | random_state фиксирован, версия модели логируется |
| NFR-08 | Расширяемость            | Добавление архитектуры без переписывания веб-слоя |
| NFR-09 | Поддержка форматов       | GeoTIFF, PNG, JPEG → GeoJSON, CSV, PDF            |
